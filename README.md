# RAGFlow on Railway

This repo packages [RAGFlow](https://github.com/infiniflow/ragflow) **v1.0.0** as a Railway template. RAGFlow is an open-source RAG (retrieval-augmented generation) engine: it parses PDFs, Office files, scans and web pages into searchable chunks, and answers questions over them with citations, through chat assistants, search apps and agent workflows.

Every service builds from a folder of this repo. Each folder has a Dockerfile that pins the official upstream image by version **and** digest and adds only a small start script. The layout follows RAGFlow v1.0.0's own `docker/docker-compose.yml` (Go backend, Elasticsearch, Kvrocks, NATS, MySQL, MinIO).

## What it deploys

| Service | Folder | Image | Role | Volume |
| --- | --- | --- | --- | --- |
| **RAGFlow** (public) | `ragflow/` | `infiniflow/ragflow:v1.0.0` | Web UI (nginx on port 80), API, admin console, ingestion worker and data-source syncer | none (keeps no data) |
| **Elasticsearch** | `elasticsearch/` | `elasticsearch:8.11.3` | Document engine: full-text and vector search over your chunks. Password auth | `/usr/share/elasticsearch/data` |
| **MinIO** | `minio/` | `pgsty/silo:RELEASE.2026-08-06T00-00-00Z` | S3-compatible storage for uploaded files (the maintained MinIO build that RAGFlow's compose uses) | `/data` |
| **MySQL** | `mysql/` | `mysql:8.4.13` | Metadata: users, datasets, documents, chats, agents | `/var/lib/mysql` |
| **Kvrocks** | `kvrocks/` | `apache/kvrocks:2.16.0` | Cache, locks and run state (Redis protocol, stored on disk). Password auth | `/var/lib/kvrocks` |
| **NATS** | `nats/` | `nats:2.14.2` | JetStream queue for document parsing tasks | `/data` |

Only RAGFlow has a public domain. The other services talk over Railway's private network.

## Variables

You don't fill in anything to deploy. Every password is generated by Railway, and services find each other through reference variables.

| Service | Variable | Default | Notes |
| --- | --- | --- | --- |
| RAGFlow | `DEFAULT_SUPERUSER_PASSWORD` | generated | Password of the admin console account `admin@ragflow.io`, used only on the first start |
| RAGFlow | `RAGFLOW_SECRET_KEY` | generated | Signs login tokens |
| RAGFlow | `MYSQL_*`, `ES_HOST`, `ELASTIC_PASSWORD`, `MINIO_*`, `KVROCKS_HOST`, `REDIS_PASSWORD`, `NATS_HOST` | references | Wiring to the other services |
| RAGFlow | `PORT` | `80` | nginx inside the image listens on 80 |
| MySQL | `MYSQL_ROOT_PASSWORD` | generated | |
| Elasticsearch | `ELASTIC_PASSWORD` | generated | Password of the `elastic` user |
| MinIO | `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` | `ragflow` / generated | |
| Kvrocks | `REDIS_PASSWORD` | generated | |

Fixed settings (Elasticsearch as document engine, MySQL as database, CPU mode, self-registration off, UTC) are baked into `ragflow/Dockerfile`.

## After deploy

1. Open the RAGFlow service's public URL and add `/admin`. Log in as `admin@ragflow.io` with the value of `DEFAULT_SUPERUSER_PASSWORD` from the RAGFlow service's **Variables** tab. This is the admin console. The admin account can't use the main app.
2. Under **User management**, create your own user account (and one for each teammate). Self-registration is off, so nobody else can sign up on your URL.
3. Log in at the public URL with your new account. Open **Model providers** and add an LLM and an embedding model (OpenAI, Anthropic, Gemini, Ollama, …). API keys go into RAGFlow's UI, not into Railway.
4. Create a dataset, upload documents and parse them, then build a chat assistant or an agent on top.

To let people sign up themselves, set `ENABLE_REGISTER=1` on the RAGFlow service. Changing `DEFAULT_SUPERUSER_PASSWORD` later has no effect: change the admin password in the admin console instead.

## Resources

Elasticsearch runs with a 1 GB heap and uses about 1.6 GB of memory. RAGFlow uses about 0.7 GB idle and more while parsing large documents. MySQL about 0.5 GB. The others are small. Parsing large PDFs is CPU-heavy.

## Not included

- **GPU** (`DEVICE=gpu`) and the local TEI embedding server: Railway has no GPUs. Use a hosted embedding model.
- **The code sandbox** (`sandbox-executor-manager`) for the agent code tool: it needs the Docker socket and privileged mode.
- **Infinity, OpenSearch, OceanBase** and the other document engines: this template uses Elasticsearch, RAGFlow's default.

## Updates

Railway sends deployers an "update available" notice when this repo's `main` branch changes. Each change bumps a pinned version and digest and adds an entry to [`CHANGELOG.md`](CHANGELOG.md), with breaking changes listed first. Read it before you apply an update. RAGFlow migrates its database on start. Back up the MySQL and MinIO volumes before a major upgrade.

## Local test

Each folder builds with `docker build`. Run them on one Docker network with the variables in the table above (hosts are the service names). The template was tested this way and on Railway before publishing.
